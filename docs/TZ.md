# ТЗ: «Календарь релизов» YADRO

Внутренний веб-сервис для команды маркетинга: календарь выхода продуктов на год, карточки продуктов со ссылками, файлами и командой, режим администратора.

Документ написан для исполнителя — Claude Code. Главное правило: **реализовать ровно то, что описано здесь и показано в эталонных экранах `design/screens/`. Ничего не добавлять от себя** — ни элементов интерфейса, ни функций, ни «улучшений» дизайна. Там, где ТЗ молчит, используется поведение браузера по умолчанию (нативные `confirm()`, `alert()`, `prompt()`, `<select>`, `<input type="color">`), а не новые придуманные окна.

## 1. Принцип точного соответствия дизайну

1. Эталон — файлы `design/screens/*.html`. Каждый элемент, отступ, размер шрифта, цвет, радиус, тень и текст подписи переносятся **один в один**. Значения берутся прямо из инлайн-стилей эталона.
2. Разрешено (и нужно) вынести повторяющиеся стили в CSS-классы и переменные (раздел 3), но **вычисленные стили** (`getComputedStyle`) элементов должны совпадать с эталоном.
3. Тексты интерфейса — дословно как в эталоне (регистр, тире «–» и «—», точки, «ё»).
4. Значения в квадратных скобках в эталоне (`[Имя Фамилия]`, `[автор]`, `[Короткое описание…]`) — это заглушки: на их месте выводятся реальные данные.
5. Иконки — те же инлайн-SVG, что в эталоне (скопировать `path`). Эмодзи не использовать.
6. Запрещено: подключать UI-библиотеки (Bootstrap, Tailwind, MUI и т. п.), менять шрифты, цвета, сетку, добавлять анимации, кроме указанной (поворот стрелки группы 0.15s).

## 2. Стек и запуск

- **Node.js 20 LTS**, **Express**, база **SQLite** через `better-sqlite3`, загрузка файлов — `multer`, сессии — `express-session` (хранилище в SQLite), пароли — `bcryptjs`.
- Фронтенд — **чистые HTML + CSS + JavaScript** (ES-модули, без фреймворка и без сборщика). Страницы отдаются Express как статические шаблоны, данные подгружаются через JSON API.
- Команды:
  - `npm install` — установка;
  - `npm run seed` — создать базу и загрузить `data/seed.json`;
  - `npm run seed:demo` — дополнительно загрузить `data/demo.json` (для сверки с эталоном);
  - `npm start` — запуск на `http://localhost:3000`;
  - `npm test` — визуальные тесты (раздел 12).
- Настройки в `.env` (создать `.env.example`): `PORT=3000`, `SESSION_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `UPLOAD_DIR=./storage/uploads`, `MAX_UPLOAD_MB=200`.
- Файлы хранятся на диске в `UPLOAD_DIR`, база — `./storage/app.db`. Папку `storage/` добавить в `.gitignore`.

### Шрифт

- `font-family: 'TT Norms Pro', Manrope, system-ui, sans-serif`. Фирменный TT Norms Pro подключается через `@font-face`, когда заказчик передаст файлы (положить в `public/fonts/`). До этого работает Manrope из Google Fonts (`wght@300;400;500`) — как в эталоне.
- Начертания: 400 — основной текст и заголовки; 500 — акценты и подписи кнопок; 300 — **только названия продуктов**.
- Трекинг 0, без `text-transform: uppercase`.

### Радиусы и размеры

- Карточки и панели — 12 px; кнопки и поля — 8 px; маленькие кнопки, чипы, бейджи — 6 px; полоски этапов — 4 px (в календаре), 2–3 px (мини-полоски).
- Высота полей ввода и основных кнопок — 44 px, кнопка «Войти» — 48 px, иконки-кнопки — 32–44 px.
- Боковая панель: развёрнутая `flex: 1 1 256px; min-width: 232px; max-width: 280px`, свёрнутая — 72 px.
- Таблица календаря: колонка продукта 248 px + 12 равных колонок месяцев, `min-width: 1000px`, горизонтальная прокрутка внутри карточки.

### Фирменный линейный паттерн

Треугольная сетка (SVG `pattern` 60 × 103.92, линии 1 px), всегда **от правого края**, с градиентной маской 0 → 100 % непрозрачности слева направо. Код — в эталонах (шапка календаря, карточка продукта, окно входа, мобильная шапка). Копировать как есть, у каждого паттерна уникальный `id`.

## 4. Роли

- **Сотрудник** (без входа): смотрит всё, фильтрует, ищет, **добавляет ссылки и файлы** к продуктам, скачивает файлы.
- **Администратор** (вход по логину и паролю): дополнительно добавляет, редактирует и удаляет продукты, их сроки и команду; добавляет, переименовывает, перекрашивает и удаляет направления и статусы.
- Сотрудник **не видит** кнопок администратора (карандаши редактирования, корзины, поля добавления, «Добавить продукт», «+ Продукт в направление»). Видит только один карандаш рядом с заголовками «Направления» и «Статусы» — он открывает окно входа.
- Вход действует во всех разделах до нажатия «Выйти» (сессия 12 часов). Администраторы хранятся в таблице `admins`; первый создаётся из `ADMIN_LOGIN`/`ADMIN_PASSWORD` при `npm run seed`.
- Все изменяющие API для администратора защищены на сервере (`requireAdmin`), а не только скрыты в интерфейсе.

## 5. Модель данных (SQLite)

```
admins        (id, login UNIQUE, password_hash)
directions    (id, name UNIQUE, sort)
statuses      (id, key UNIQUE, name, sort, background, color, border NULL, is_release 0/1)
products      (id, name, direction_id → directions, description, created_at, updated_at)
stages        (id, product_id → products ON DELETE CASCADE, status_id → statuses, from_month 'YYYY-MM', to_month 'YYYY-MM')
team_members  (id, product_id → products ON DELETE CASCADE, full_name, role, contact_url, sort)
materials     (id, product_id → products ON DELETE CASCADE, kind 'link'|'file', title, url NULL, category, pinned 0/1, note NULL, author, created_at)
file_versions (id, material_id → materials ON DELETE CASCADE, version, stored_name, original_name, size, mime, author, created_at)
date_history  (id, product_id → products ON DELETE CASCADE, text, reason NULL, author, created_at)
```

- У статуса GA `is_release = 1`: по нему считаются «Выходы в GA», «Ближайшие выходы в GA», подпись «GA — апрель», мобильные месяцы. Признак ставится в seed, в интерфейсе не меняется.
- Категории материалов — фиксированный список в коде: **Презентации, Макеты, Визуалы, Документы, Тексты, Сайт, Другое**.
- При `npm run seed` для каждого продукта создаётся запись истории «Сроки внесены: GA — {месяц год}» с автором «Импорт из таблицы» и датой `2026-10-27` (дата импорта таблицы заказчика).
- `npm run seed:demo` берёт `data/demo.json`: описание, команду, историю и 10 материалов для TATLIN.UNIFIED G3; для файлов создаёт пустые файлы-заглушки с указанными именами и номерами версий.
- Даты в интерфейсе: «24 окт» (число + сокращённый месяц в родительном падеже, без года), месяцы в сроках — «январь», «апрель 2027».

## 6. Экран «Календарь» (`/`)

Эталоны: `01-calendar.html` (сотрудник), `01a-calendar-login.html` (окно входа), `01b-calendar-admin.html` (администратор), `01c-calendar-groups-collapsed.html` (свёрнутые группы), `01d-calendar-nav-collapsed.html` (свёрнутая панель).

**Боковая панель**
- Логотип (синий), подпись «Календарь релизов», кнопка «Свернуть панель». Свёрнутая панель — 72 px, тёмно-синяя кнопка «Развернуть панель» и три иконки разделов. Состояние панели хранится в `localStorage` и общее для всех страниц.
- Плашка «Режим администратора» с кнопкой «Выйти» — только у администратора.
- Меню: Календарь, Все продукты, Файлы и ссылки; активный пункт подсвечен.
- «Направления»: список с галочками (фильтр строк календаря, по умолчанию все отмечены, состояние в `localStorage`), справа число продуктов. Длинные названия переносятся, не обрезаются.
  - Администратор вместо числа видит «Переименовать» (`prompt()` с текущим названием) и «Удалить» (`confirm()`; если в направлении есть продукты — `alert('Нельзя удалить: в направлении есть продукты. Сначала перенесите их в другое направление.')`). Внизу поле «Новое направление» и кнопка «+».
- «Статусы»: образец цвета и название.
  - Администратор: образец становится кнопкой (открывает `<input type="color">`; для статуса с обводкой меняются обводка и текст, для залитого — фон, цвет текста выбирается автоматически: белый или чёрный, у какого контраст выше). «Переименовать», «Удалить» (запрет, если статус используется: `alert('Нельзя удалить: статус используется в сроках продуктов.')`), поле «Новый статус» + «+» (новый статус: фон `#E0E0F5`, текст `#000000`).
- «Выходы в GA · {год}»: сетка 12 месяцев (3 колонки). В месяце — квадратики по числу продуктов с GA в этом месяце, месяцы с выходами на фоне `--steel-light`. Элемент некликабельный. Подпись «Квадратики — сколько продуктов выходит в GA в этом месяце».

**Шапка**
- H1 «Календарь выхода продуктов», переключатель года (‹ 2027 ›), строка «{N} продуктов · {M} направления» (склонения по-русски; считаются продукты, у которых есть этапы в выбранном году). Год по умолчанию — текущий, если в нём есть этапы; иначе ближайший следующий год с этапами (сейчас это 2027). Выбранный год общий для календаря, «Все продукты» и телефона, хранится в `localStorage`.
- Поиск «Найти продукт» — фильтрует строки по подстроке названия без учёта регистра; группы без совпадений скрываются.
- Кнопка «Добавить продукт» — только у администратора, открывает окно продукта в режиме создания.
- Паттерн справа.

**Панель над таблицей**: «Свернуть все», «Развернуть все», справа легенда этапов.

**Таблица**
- Шапка: «Продукт» и 12 сокращённых месяцев (Янв…Дек).
- Группа-направление — кнопка на всю ширину: стрелка, название, «N продуктов», в свёрнутом виде синим «GA: февраль, апрель, август» (уникальные месяцы GA группы). Свёрнутость групп в `localStorage`.
- Строка продукта: название (300, 16 px, переносится) — ссылка на карточку; под ним «GA — {месяц}»; у администратора справа карандаш — открывает окно редактирования. Полоски этапов по месяцам выбранного года (этапы за пределами года обрезаются по краю), в полоске — название статуса.

**Ближайшие выходы в GA**
- Карточки продуктов, у которых месяц GA попадает в 6 месяцев, начиная с `max(текущий месяц, январь выбранного года)`, в пределах выбранного года. Сортировка по месяцу GA.
- Подзаголовок: «первое полугодие {год}», если диапазон январь–июнь; иначе «{месяц} – {месяц} {год}».
- Карточка: «Апр 2027», название, направление, строка «Pre-GA: январь – март. После GA — поддержка продаж» или «Без этапа Pre-GA. После GA — поддержка продаж». Клик — карточка продукта.

**Окно входа** (`01a`): синяя шапка с паттерном и белым логотипом, крестик, «Вход для администратора», поля «Логин» и «Пароль», кнопка «Войти». При ошибке — `alert('Неверный логин или пароль')`. Закрытие по крестику, по клику на затемнение и по `Esc`.

- «← Все продукты».
- Шапка с паттерном: направление, название (300, 48 px), описание (если пусто — блок не выводить), кнопка «Скопировать ссылку» (копирует URL страницы в буфер).
- Три плашки сроков: Pre-GA «январь – март», синяя «Выход в GA / апрель 2027 / через 6 месяцев», «Поддержка продаж / с мая». Отсчёт: «через N месяцев» (склонения), «в этом месяце», «вышел» — от текущего месяца. Если этапа нет — плашка не выводится.
- Полоска этапов на 12 месяцев с подписями месяцев.
- «Закреплённые ссылки»: все ссылки продукта, новые сверху, плитки: метка (по домену, правило из раздела 8), название, вторая строка — `note`, если задан, иначе «обновлено {дата}». Клик открывает ссылку в новой вкладке. Кнопка «+ Ссылка» — окно материала на вкладке «Ссылка».
- «Файлы»: все файлы продукта (последние версии, новые сверху): бейдж-расширение, имя, «{note · }версия N», «{дата} · {автор}», кнопка «Скачать файл». Кнопка «+ Файл», зона «Перетащите файлы сюда…» — перетаскивание открывает окно материала на вкладке «Файл» с этими файлами.
- «Команда»: инициалы (первые буквы первых двух слов ФИО, только буквы), ФИО, роль, кнопка связи с названием канала: ссылка на `t.me`/`telegram` → «Telegram»; `mailto:` или адрес с `@` → «Почта» (ссылка `mailto:`); иначе → «Написать». Подпись «Команду меняет администратор в форме продукта».
- «История сроков»: записи новые сверху, у первой синяя точка, у остальных `#C9C9EA`. Первая строка — текст записи («GA: апрель 2027 → май 2027» или «Сроки внесены: GA — апрель 2027»), вторая — «{причина} · {дата}, {автор}» или «{дата}, {автор}», если причины нет.

## 10. Модальные окна

### 10.1 Продукт — создание и редактирование (только администратор)

Эталон: `05-product-edit-admin.html` (режим редактирования).

- Плашка «Режим администратора», заголовок «Редактирование продукта» (в режиме создания — «Новый продукт», поля пустые, без кнопки «Удалить продукт»).

- «Этапы и сроки — с точностью до месяца»: строки «Статус | С | По | корзина». «С» и «По» — `<select>` с месяцами «Январь 2027» на диапазон «год − 1 … год + 2». «Добавить этап» добавляет строку со следующим по порядку неиспользованным статусом (кнопка неактивна, если все статусы использованы). Проверка: «С» ≤ «По», иначе `alert('Дата начала этапа позже даты окончания')`.
- Превью «Так продукт будет выглядеть в календаре {год}» — живая мини-полоска.
- «Команда продукта — видна всем в карточке продукта»: строки «ФИО | Роль | Как связаться | корзина», «Добавить участника», подсказка про формат ссылки.
- «Причина изменения сроков» — если сроки изменились, при сохранении создаётся запись истории с этой причиной.
- Низ: «Удалить продукт» (`confirm('Удалить продукт и все его материалы?')`), «Отмена», «Сохранить».

### 10.2 Материал — ссылка или файл (доступно всем)

Эталон: `06-add-material.html` (слева вкладка «Ссылка», справа «Файл»).

- Переключатель «Ссылка / Файл».
- Ссылка: «Адрес ссылки», «Название» (сервер пытается получить `<title>` страницы с таймаутом 3 с и подставляет его; тогда показывается подсказка «Подставили из ссылки — можно поменять»), «Продукт», «Тип материала». Кнопка «Добавить».
- Файл: зона «Перетащите файлы или выберите на компьютере», подпись о форматах «PDF, PPTX, DOCX, XLSX, изображения, ZIP — до 200 МБ», список загружаемых с прогрессом и крестиком отмены. Если у продукта уже есть файл с таким именем — плашка «Файл с таким именем уже есть. Сохраним его как версию N, версия N−1 останется в истории» и файл сохраняется новой версией того же материала. «Продукт», «Тип материала», кнопка «Загрузить».
- Автор материала: логин администратора, если вошёл администратор; иначе «Сотрудник» (см. открытые вопросы).

## 11. Телефон (ширина ≤ 768 px)

- `/` — эталоны `07-mobile-calendar.html`, `07a-mobile-calendar-august.html`: синяя шапка с белым логотипом и паттерном, «Выходы в GA», «{год} · {N} продуктов». Чипы — только месяцы выбранного года, где есть GA, с квадратиками-счётчиками. По умолчанию выбран ближайший месяц с GA, начиная с текущего (иначе первый). Ниже «{Месяц} — выход в GA» и карточки продуктов: название, «{направление} · Pre-GA {месяц} – {месяц}» или «· без этапа Pre-GA».

## 12. Критерии приёмки

1. `npm install && npm run seed && npm run seed:demo && npm start` запускает сервис без ошибок.
2. **Визуальные тесты** (`npm test`, Playwright, Chromium): для каждого эталона из `design/screens/` открыть соответствующую страницу приложения в том же состоянии (сотрудник / администратор / окно входа / свёрнутые группы / свёрнутая панель / вкладка «Ссылки» / август на телефоне) при 1440 × 900 и 390 × 844, снять скриншот и сравнить со скриншотом эталона: для десктопа — всей страницы, для телефона — первого экрана 390 × 844 (эталоны телефона обрезаны по высоте экрана). Допуск — не более 1 % отличающихся пикселей (`maxDiffPixelRatio: 0.01`). Для стабильности: дата в тестах зафиксирована на 27 октября 2026 (`page.clock`), шрифт Manrope, база после `seed` + `seed:demo`. Ссылки в «Ближайших выходах в GA» и в эталонах ведут на карточку TATLIN.UNIFIED G3 — это особенность эталонов, в приложении каждая карточка ведёт на свой продукт.
3. Данные календаря совпадают с `data/seed.json`: 10 продуктов, 4 направления, сроки по месяцам.
4. Сотрудник не видит кнопок администратора; прямые запросы к API администратора без входа возвращают 401.
5. Загрузка файла с тем же именем создаёт новую версию; скачивается последняя.
6. Контраст текста не ниже 4.5:1, у полей ввода рамка 3:1; все кнопки — настоящие `<button>`, ссылки — `<a href>`, у иконок-кнопок `aria-label` как в эталоне.
